## 1. The measured diagnosis (why we're at 62%)

Error decomposition over 80 wrong gold-classify cases (replayed real L0→L3 + rerank), **corroborated by two independent papers** (arXiv 2605.14857 deterministic-HS-workflow: 22% recall vs 65% ranking error; arXiv 2509.18400 ATLAS: ~75% 8-digit cliff, "sibling confusion" = primary bottleneck):

| Bucket | Share | Meaning |
|---|---|---|
| **SELECTION** | **75%** (60/80) | gold leaf WAS in L4's ≤8 set, L4 picked a wrong sibling. **36/60 had gold in the reranker top-2.** 45/60 same 4-digit heading; 19/60 same 6-digit subheading. |
| RETRIEVAL | 25% (20/80) | gold never reached L4. ~half = L1 triage wrong chapter (TC009 pump→84; TC306 saree→50); ~half = genuine L2 leaf-recall. |
| RERANK-as-drop | 0% | reranker never dropped a retrieved gold (it's an ordering signal, folded into selection). |

**Honest ceiling (must internalize):** non-fine-tuned frontier+RAG systems report ~64–75% top-1 / ~78–91% top-3 at 6–8 digit. 62% is **in-band, not broken.** 80% top-1 without fine-tuning is the *optimistic edge*. **Realistic end-goal = ~75–80% top-1 via the levers below + a calibrated ASK path that converts genuinely-ambiguous siblings, with a fine-tuned domain reranker as the later true ceiling-raiser.** Report **top-1 AND top-3** as product metrics.

## 2. Root cause (mechanistic — from codebase analysis)

The 8-digit gap is structural, two coupled defects:
1. **No guaranteed sibling co-surfacing.** L2's cosine leaf query is `ORDER BY <=> q LIMIT 10` *global* across the 5 candidate subheadings (no per-subheading floor); siblings under the gold's subheading co-surface only *incidentally* (FTS luck or cosine slots). Once a leaf is in the union, **nothing pulls in its enumerated siblings** → L4's `computeSiblingDiscriminators` group often has <2 members → L4 picks blind among an incomplete sibling set. `L2-retrieval.ts` cosine cascade + `supabase-client.ts:317-344`.
2. **Reranker + L4 are blind to the distinguishing attributes.** RerankDocument = only `Chapter|Heading|Subheading|description`; near-identical siblings get near-identical scores; temp=0 ties them → tie-break = cosine order (not relevance). The 500-char cap clips the discriminating description *tail*. `reranker.ts:129-157`. (This is also why gate-1's L4-prompt-only fix was neutral — the inputs were incomplete/undifferentiated.)

- **L-A Sibling expansion** (M, retrieval): after the L2 union, fetch ALL `tariff_line` children of the top-reranked leaves' subheadings and add missing siblings BEFORE rerank → guarantees the right leaf + true competitors reach L4 together. `L2-retrieval.ts:424-455` + reuse `getTariffLinesForSubheadings` (`supabase-client.ts:498`). **Dominant fix.**
- **L-B Discriminating attributes into rerank docs** (M, rerank): append a compact `tariff_line_attributes` discriminator line to each RerankDocument so the reranker can actually separate siblings. `L2-retrieval.ts:482-493`.
